# t18-parsers.md — V8 bytecode/deopt parsers + golden fixtures (plan todo 18)

Date: 2026-08-24 · Executed by: Sisyphus session

## Scope delivered

- NEW workspace package `packages/engine-parsers` (NodeNext, strict,
  noUncheckedIndexedAccess, verbatimModuleSyntax).
- `src/v8-bytecode.ts` — block parser for `d8 --print-bytecode`:
  headers `[generated bytecode for function: <name> (0x… <SharedFunctionInfo>)]`
  (V8 ≥13 pointer suffix stripped; legacy short form also matches),
  Parameter/Register/Frame header fields (colon optional per real output),
  instruction rows → {offset, bytecode, operands[], sourceHint?} with the raw
  byte column stripped, Constant pool / Handler Table sections captured as
  line arrays. Tolerance channel: unknown lines attach to the nearest block
  (`rawLines`) or the preamble — the parser NEVER throws.
- `src/v8-deopt.ts` — bailout-line parser extracting
  {kind, reason, functionName, bytecodeOffset} from REAL `--trace-deopt`
  output shape `[bailout (kind: deopt-eager, reason: not a Smi): begin.
  deoptimizing 0x… <JSFunction f (sfi = …)>, … bytecode offset 2 …]`.
- Fixtures generated from the REAL d8-debug canary **15.4.45**:
  `v8-bytecode-big.golden.txt` (generated big() with 1204 instructions —
  exceeds the ≥200 bar), `v8-bytecode-truncated.golden.txt`,
  `v8-deopt.golden.txt`. Generator-version headers documented in QA file;
  regeneration script `pnpm gen-fixtures` (RH_NET_TESTS=1 gated vitest spec
  `src/gen-fixtures.test.ts` re-captures from a fresh canary download).
