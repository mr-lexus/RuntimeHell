# t20-wrapping.md — SelectionService wrapping strategies (plan todo 20)

Date: 2026-08-24 · Executed by: Sisyphus session

## Scope delivered

- `apps/renderer/src/editor/wrapping.ts` — deterministic per-kind wrappers:
  · expression → `__rh_out(__rh_repr(<expr>))` with a structural repr prelude
    (depth-capped, cycle-safe, engine-agnostic output via print/console.log)
    — the fallback transport for shells without the ResultCapture bootstrap
  · function/class → verbatim source; optional "sample invocation" appends
    `fn.apply(null, Array.from({length: fn.length}, () => undefined))` inside
    try/catch (default OFF for analysis)
  · statement/block → async IIFE (top-level await safe)
  · module → verbatim
  · `extractDefinitionName` best-effort name detection feeding functionName
- AnalysisManager persists the EXACT snippet to
  `<workspace>/.rhbuild/analysis/<requestId>.mjs` when workspaceId is sent
  (protocol field added; best-effort, never blocks analysis).
- Drawer: "show generated wrapper" toggle renders the exact emitted code
  before results arrive.
- CodeEditor context-menu Analyze actions now pass SelectionInfo (kind + text);
  App routes through `requestFromSelection` (wrapping happens renderer-side,
  matching plan's "SelectionService output" contract).
